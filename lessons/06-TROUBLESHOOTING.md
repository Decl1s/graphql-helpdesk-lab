# Как я разбираюсь, если что-то не получилось

Я начинаю с первого сбоя, а не меняю всё сразу. Я проверяю папку, запущен ли сервер, какой адрес собрал Bruno, какую роль и какие данные отправил. После исправления предусловий я повторяю опыт.

| Что я вижу | Что я сначала проверяю | Что я делаю |
| --- | --- | --- |
| npm не найден | Я проверяю установку Node.js и перезапуск терминала после установки | Я устанавливаю подходящий Node из официального источника |
| ENOENT с package.json | Я проверяю текущую папку терминала | Я открываю терминал рядом с package.json этой копии |
| Cannot find package | Я проверяю, выполнил ли npm ci и завершился ли он успешно | Я устанавливаю зависимости; не копирую отдельный пакет вручную в node_modules |
| Ошибка неподходящей версии Node | Я читаю node --version и engines в package.json | Я использую Node 24.22.0 |
| ECONNREFUSED в Bruno | Я проверяю, продолжает ли работать npm start | Я запускаю сервер и сверяю Local с адресом из терминала |
| В URL осталось {{baseUrl}} | Я проверяю выбранное окружение | Я выбираю Local |
| Порт 8767 занят | Я проверяю свои открытые терминалы | Я останавливаю предыдущий экземпляр; для автоматического опыта использую demo |
| В браузере нет страницы приложения | Я вспоминаю, что встроенная GraphiQL отключена | Я открываю запросы в Bruno, а не ожидаю сайт по адресу API |
| HTTP 400 | Я читаю errors и отправленные Variables | Я ищу неизвестное поле, опечатку enum или неверный тип JSON |
| HTTP 200, но Assert красный | Я читаю data и errors, затем ожидаемое значение | Я различаю ошибку ожидания, предусловия и реальный дефект |
| T-2001 не найден | Я проверяю, выполнял ли 11 после последнего reset | Я начинаю последовательность заново |
| При создании вернулся T-2002 | Я проверяю, создал ли уже запись в этом процессе | Я выполняю reset перед эталонным прогоном |
| 16 стал красным после 15 | Я проверяю первый ответ и режим training-bug | Я расследую запрещённую запись в 15 как первопричину |
| Tests 0/0 | Я смотрю строку Assertions | Я ожидаю 83/83 Assert; JavaScript Tests в наборе не нужны |
| check показывает красный training-bug | Я смотрю итог всего check и фразу о подтверждённом дефекте | Я различаю ожидаемый промежуточный отказ и отказ самого gate |
| Не вижу комментариев в JSON | Я помню, что JSON не поддерживает комментарии | Я читаю урок 4 и Docs, не вставляю // в Variables |

## Как я отличаю ожидание от факта

Если я попросил T-1003, а Assert всё ещё требует T-1001, я сначала исправляю собственный кейс. Если я попросил T-1001 с верной ролью и верным ожиданием, но сервер вернул другое, я собираю минимальные шаги и сверяю контракт. Наличие красного цвета само по себе не показывает, кто ошибся.

Я не исправляю тест заменой ожидаемого значения на любой полученный ответ. Сначала я объясняю, почему новый результат должен быть правильным. Иначе я могу превратить обнаруженный дефект в зелёную проверку.

## Как я восстанавливаю чистое начало

Я прекращаю параллельные ручные прогоны, выполняю 01-reset от staff и запускаю коллекцию по порядку. Для более полного сброса я останавливаю только свой учебный сервер через Ctrl+C и запускаю заново. Я не удаляю исходники и не завершаю неизвестные системные процессы ради занятого порта.

## Что я прикладываю к вопросу или багу

Я записываю версию Node, имя запроса, режим сервера, выбранную роль, Variables, HTTP-статус, ключевые data/errors и ожидаемый результат. Я могу показать свой изменённый Assert. Перед передачей отчёта я просматриваю его: Bruno может включать абсолютные пути моей папки. Реальные контакты, секреты и чужие рабочие данные в этот стенд я не добавляю.

## Как я понимаю ошибки установки

Для обычной установки нужен доступ к npm registry. Если сеть недоступна, я не называю это ошибкой GraphQL: запросы ещё не запускались. В моей среде для копии я использовал уже наполненный локальный cache, но не обещаю такой cache на другом компьютере. Стандартная команда в README рассчитана на обычную установку из реестра.

Если npm audit в будущем сообщает новый advisory, я проверяю его и совместимое исправление, затем повторяю регрессию. Я не применяю audit fix --force наугад и не выдаю старый нулевой аудит за актуальную гарантию.
