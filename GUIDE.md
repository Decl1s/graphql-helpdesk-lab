# Как я прохожу стенд за 10 минут

## 1. Я запускаю готовый API — 2 минуты

Я выполняю две команды из README, оставляю `npm start` открытым. Если я вижу сообщение о занятом порте, я останавливаю старый экземпляр стенда. Я не завершаю чужие процессы наугад. Для полностью автоматического прогона я вместо этого использую `npm run demo`: он сам выбирает свободный порт.

## 2. Я открываю коллекцию — 1 минута

В Bruno я выбираю **Open Collection**, папку `collection`, затем окружение **Local** в переключателе окружений. Я открываю `00-health`, нажимаю **Send** и смотрю JSON ответа. Если адрес содержит неразрешённый `{{baseUrl}}`, я проверяю выбор Local. Для локального стенда я отключаю прокси в настройках коллекции, если мой прокси перехватывает localhost.

## 3. Я разбираю окно запроса — 2 минуты

| Часть окна | Что я там меняю | Зачем |
| --- | --- | --- |
| URL | `{{baseUrl}}/graphql` | Я выбираю адрес стенда через окружение |
| Headers | `X-Demo-Actor` | Я выбираю `customer-a`, `customer-b` или `staff` |
| GraphQL / Query | Поля внутри `{ }` | Я указываю, какие данные хочу получить |
| Variables | JSON для `$id`, `$input` | Я меняю данные отдельно от структуры запроса |
| Assert | Expression, Operator, Value | Я задаю проверяемый результат без скрипта |
| Response | `data`, `errors`, HTTP status | Я сверяю факт с ожиданием |

Названия и расположение вкладок я сверяю со своей установленной версией Bruno. Я не путаю вкладку Assert с JavaScript-вкладкой Tests. Например, в `03-own-ticket` я вижу Expression `res.body.data.ticket.id`, Operator `eq`, Value `T-1001`. Для отсутствия ошибки я использую `res.body.errors`, `isUndefined`, без значения.

## 4. Я вижу особенность GraphQL — 2 минуты

Я запускаю `07-foreign-ticket`: ожидаю HTTP 200, `ticket: null`, `errors[0].extensions.code: FORBIDDEN`. Я запускаю `08-partial-error`: сохраняются `id` и `title`, а `internalNote` становится `null`; путь ошибки указывает на это поле. Я запускаю `09-unknown-field`: при моём `Accept: application/graphql-response+json` ожидаю HTTP 400 и отсутствие `data`.

## 5. Я выполняю регрессию — 1 минута

Я выбираю **Run Collection** / Runner и запускаю **всю коллекцию последовательно**, без параллельного исполнения. `01-reset` восстанавливает исходный набор, `11-create` создаёт `T-2001`, последующие запросы используют его. Я не запускаю два Runner одновременно на одном сервере. Если я выполнял запросы вручную в произвольном порядке, я начинаю новую полную последовательность с reset.

## 6. Я нахожу дефект — 2 минуты

Я останавливаю обычный сервер и запускаю:

```sh
npm start -- --training-bug
```

Я повторяю всю коллекцию. В `15-customer-forbidden` я ожидаю красные Assert: клиент смог изменить статус. Следующий `16` тоже может стать красным, поскольку `15` уже изменил состояние. Я расследую **первое смысловое расхождение** и заполняю [BUG_REPORT.md](BUG_REPORT.md). Для возвращения к исправному режиму я останавливаю сервер и выполняю обычный `npm start`.

## Где я редактирую проект

| Файл | Что я в нём делаю |
| --- | --- |
| `collection/*.bru` | Я сохраняю запросы, переменные, заголовки и Assert; Bruno редактирует эти файлы за меня |
| `collection/environments/Local.bru` | Я меняю адрес; реальные секреты сюда не записываю |
| `src/schema.graphql` | Я читаю допустимые поля, типы и enum |
| `src/app.js` | Я меняю правила готового учебного стенда, если уже хочу немного программировать |
| `src/server.js` | Я вижу фиксированный localhost-порт и явный режим дефекта |
| `scripts/run-collection.js` | Я вижу, как коллекция запускается автоматически и сохраняет отчёты |
| `tests/api.test.js` | Я нахожу дополнительные граничные проверки реализации |
| `scripts/ci.js` | Я вижу проверку зелёной коллекции и обнаружения намеренной ошибки |
| `SOURCE_FILES.txt` | Я разрешаю только конкретные файлы для архива и публикации |

Для первого самостоятельного изменения я копирую `03`, выбираю `T-1003` и добавляю Assert статуса `RESOLVED`. Затем я перехожу к пяти заданиям из NOTES. Я сохраняю свою копию отдельно, чтобы не потерять исходный эталон.
